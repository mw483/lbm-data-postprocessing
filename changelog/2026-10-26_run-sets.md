# Run sets: comparison outputs no longer overwrite each other (2026-10-26)

**Commits**: `b221977`, `e36036e`, `e3742d7`, and the follow-up `03524d0` (range `c05473d..e3742d7`, follow-up range `c0c2ff7..03524d0`, branch `analysis/scalar2-outputs`)

**Goal**: Mikael wants to compare the old convective run (before the SGS fix) with the new one. The comparison scripts had a hard-coded `CASES` dict and fixed output folders, so a second comparison would overwrite the first one's figures. The output must be designed so that this cannot happen.

**Result**: pytest: 72 passed, 1 failed. The failure is `test_streamed_trajectories_read_11_column_file`, an existing failure with polars 2.0 that has nothing to do with this change. New `tests/test_run_sets.py` has 9 tests. pyflakes is clean on the changed files. Cloud smoke test with synthetic particle bins for 3 runs (one under `lbm_results`, two under `lbm_reduced`), reduced with `scripts/reduce_particle_bins.py`, then `plot_particle_bin_stats` with a 2-run default set and a 3-run set: separate output folders, all figures and CSV files written, `runs.yaml` correct, the CSV `case` column holds all 3 labels, the `z_pdf_vs_age.png` figure has 3 panels. **Not checked**: the CBL-scaled figure and the Eulerian lines with real `prof` files; the other six scripts were only lint-checked, not run (no solver or C++ data in the cloud); nothing was run on Mikael's PC.

## Context

Mikael's request (2026-10-26): "If I want to compare the old convective SGS and the new convective SGS, the outputs all go to the same folder and gets overwritten. How do we design the output to prevent this?"

The design proposed: named run sets in a tracked YAML file, `--set NAME` on the scripts, outputs in `<figures>/<set>/<topic>/`, a `runs.yaml` manifest in each output folder, and the default set equal to today's pair of runs. Mikael approved it with three conditions:

1. YAML is fine, but a comparison must be able to hold more than 2 runs.
2. Move the figures that are already committed, keeping in mind that figures of the old analysis suite exist.
3. The new convective run after the SGS fix is `20261026_scalar2`. Its reduced data is at `Z:\lbm_reduced\flat_512x128x1024\20261026_scalar2\particle_reduced` (Z: is the rclone mount of TSUBAME).

The SGS fix itself is in LBM-city `mikael/cases`, commit `d154fd2`: the particle MPI datatype now sends `u/v/w_sgs`. It answers the suspicion in [2026-10-20_particle-bin-statistics-animation.md](2026-10-20_particle-bin-statistics-animation.md). This entry only prepares the comparison; it does not show that the fix works.

## Decisions

- Any number of runs per set. The order in the file is the colour order (`C0`, `C1`, ...).
- The label in front of each run is the legend name and the value in the `case` column of the CSV files. Keep labels short and unique within a set.
- Add new sets instead of editing a set that already has figures.
- Optional `local_paths.yaml` key `lbm_reduced`. Lookup order for reduced data: `lbm_reduced` first, then `lbm_results`. This way old runs copied to D: and new runs on Z: both work.
- Figures of the old analysis suite (dated folders, `comparative`, `flat_domain`, `presentation_2026-10-07`, and so on) stay where they are on purpose. Only the outputs of the seven run-set scripts moved.

## Follow-up 03524d0: `plot_particle_bin_stats` runs without `lbm_results`

Mikael ran `plot_particle_bin_stats` on his own PC. That PC has no `D:/lbm_results` copy (storage limits). His `local_paths.yaml` has only `lbm_reduced` (`Z:/lbm_reduced`, the TSUBAME mount). The script stopped with `KeyError`: `[ERROR] set lbm_results in local_paths.yaml (folder holding <case>/<date>_<tag>/output ...)`. Cause: `e36036e` called `wind_dir()` (which needs `lbm_results`) before checking whether the run's output folder exists. The skip-with-warning rule of `e36036e` (see the table above) therefore never got a chance to run.

| File | Change | Why |
|---|---|---|
| [scripts/plot_particle_bin_stats.py](../scripts/plot_particle_bin_stats.py) | In the loop over runs for the Eulerian profiles and convective scaling, a new first check: if `lbm_results` is not in `local_paths.yaml`, print `[WARNING] <label>: lbm_results not set in local_paths.yaml; left out of the Eulerian and CBL-scaled lines` and `continue`. The existing check `wind_dir(...).is_dir()` comes after it, unchanged. The module docstring now says that any run is left out of the Eulerian lines when `lbm_results` is not set. | The particle figures only need the reduced data. They must not depend on a folder Mikael's PC does not have. |

Behaviour:

| Situation | Before `03524d0` | After `03524d0` |
|---|---|---|
| `lbm_results` not set | `KeyError`, no figure written | One warning per run. Every run is left out of the Eulerian lines and of `dispersion_vs_age_cbl.png`. All particle figures are still written, including `sgs_along_x.png`. |
| `lbm_results` set, run has no `output` folder | Warning, run skipped (from `e36036e`) | Same |
| `lbm_results` set, `output` folder present | Eulerian lines and CBL-scaled figure as before | Same |

To revert, check out the file at `c0c2ff7`.

## What was deliberately left alone

- Figures of the old analysis suite (dated folders, `comparative`, `flat_domain`, `presentation_2026-10-07`, and so on) were not moved.
- Sets that already have figures are not edited; new comparisons get a new set.
- No physics or numerics changed. Only where the scripts read run names and write files.
- The six other scripts were not run and the CBL-scaled figure was not checked with real data (see Result).
